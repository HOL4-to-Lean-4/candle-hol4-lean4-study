## 1. The most important issues, ranked

1. **Contribution (1) is circular, and "certification" claims too much.** "Translation now works, no meaning defects" rests only on Claude auditors and comparison agents plus a few HOL4 queries. Contribution (2) argues that exactly this kind of single-family check is unreliable. The 278 statements are not proved yet. A proof of all 278 would show that they are true of the Lean definitions, not that the definitions match HOL4. Proofs expose translations that are too strong (unprovable statements) and miss those that are too weak (a weakened conclusion, a dropped conjunct, an extra hypothesis). The ARS Devil's Advocate raised the circularity as its CRITICAL C1, and the editor validated it. Astra's first point says the same thing.
2. **There is no fidelity contract, so the defect labels contradict each other.** The baselines accept fixing an unspecified value (`HD [] = ARB`, `RESULT (Clash t) = t`) as a valid model with "no meaning difference". The mutant list seeds "unspecified values fixed to a default (`HD []`)" as a defect. A type signature that is equivalent but differs from HOL4's is a note in the results and a mutant in §Audit. An extra `[Nonempty]` is seeded as a defect, although every HOL type is inhabited and `Classical.epsilon` needs `Nonempty`. Until fidelity is defined (statement equivalence, preservation of the source theorems, or conservativity over the source), detection rates cannot be scored.
3. **The setups cannot show a cross-family effect.** S3 is a single Opus pass. S4 and S5 add a second model, a second stage, per-finding review, tools and more spend. A gain could come from any of these. S4 can only filter Astra's findings, so its recall can never exceed S1's. Grounding in S5 is applied to accepted findings only, so it cannot add recall either, and dropping a true positive can lower precision as well as raise it. The design lacks a same-family two-stage control, a single model with grounding, a scans-only baseline and a cost-matched single-family arm. The ARS methodology seat rated this Critical.
4. **The seeded-defect experiment is small, clustered and coached.** It has 36 defects over about 13 subtypes, so roughly 3 per type, in 6 shared copies, with one run per setup and copy. The audit brief names the seeded classes. There is no pre-specified primary comparison and no named scorer for matching findings to mutants or for judging whether a reason is correct. Even 36 detections out of 36 give a two-sided 95% lower bound of about 90% recall, and clustering weakens that further.
5. **The plan does not answer the ITP porting bar, and the related work is missing.** It does not state the transferable insight up front. (It does list, in §1, three things it adds over the FormaliSE study; the ARS Journal-Fit seat asked for a sharper statement.) It also does not position itself against typed HOL4 kernel-term export, OpenTheory, or symbolic HOL importers into Isabelle, HOL Light and Dedukti. Several of §6's "oracle" questions (overload resolution, the statements HOL4 builds with ML, the types of unused binders) disappear when the statements come from the HOL4 kernel instead of the script text.
6. **The oracle is presented as stronger than it is.** Ground evaluation and `#eval`/`decide` cannot settle quantified, higher-order or inductive claims, or anything defined through `Classical.epsilon`, which the baselines use. A failed short proof is not a refutation. The check is cited by a model, and §Grounding verifies only the findings that were accepted, so findings the reviewer wrongly rejected are never examined.
7. **Scope is too broad for 16 pages and 12 weeks.** Phase 2 is already placed after the paper in §3 and §10, but the plan still has a second prover family, two proving rounds of three runs, the Sonnet arm and repeated validation rounds. It has no outline or page budget, and the 25 Jan go/no-go tests whether proving finished, not whether the main claim holds.
8. **"No human expert" hides human expert input.** The briefs that carry study-1 lessons, the choice of mutants and their expected effects, the design of the checks and the merge fixes are all expert input, and none of it is logged. Contamination is acknowledged but not probed. The motivating evidence is reported loosely: the plan says two Claude auditors, while the 23 Nov reframing says three independent ones (two auditors and a comparison agent, in related sessions).

## 2. Where ARS and Astra agree

Both reviews raise these points independently: Astra did not see the ARS output in round 1. `gpt-6-astra` raised most points below in its round 1, and so did `gpt-6.2-astra` in its own, without seeing ARS. Quotations of Astra below are from `gpt-6-astra` round 1 unless marked 6.2. In round 2, `gpt-6.2-astra` was shown the 16 ARS points: it agreed with 12, agreed with a refinement on one (the oracle), and partly agreed on three (extra control arms, sample size and repeats, exhaustive grounding). It disagreed with none. That is less independent than round 1, because Astra was answering the ARS list.

- **Overclaiming.** Contribution (1) is not established. "Certification" exceeds the evidence. Proving shows truth relative to the Lean definitions, not fidelity. Both suggest calling the contribution an evidence-backed audit (ARS: "audit / validation evidence"; Astra: "evidence-backed translation audit").
- **The defect definition is missing.** Both cite the `HD []` contradiction and ask for the fidelity criterion to be fixed before the labels are assigned.
- **The cross-family claim is confounded.** Both ask for matched controls (Opus→Opus, Opus with grounding, a strong single auditor with the same tools and budget). Both note that S4 only filters. Both ask for joint-miss analysis before any claim that diversity helps: ARS proposes pairwise joint-miss rates against the product of marginals, Knight–Leveson style, and Astra asks for multiple models per family.
- **Sample size and power.** 36 defects is too few for per-type claims and the observations are clustered. Both want repeated runs, intervals and one primary contrast.
- **Briefs that name the classes.** Both want held-out mutant classes or a separate brief condition.
- **Mutant validity.** Each label needs a checked witness. Mutants should include defects that are provable but silently wrong, and each should be tagged by whether proving would expose it (ARS methodology W6, with which 6.2 strongly agreed in round 2; `gpt-6-astra` asked to separate definition fidelity from target-theorem impact).
- **Ground truth on clean code.** Both say to ground every finding, not only the accepted ones, and to keep an "unresolved" category.
- **Limits of the oracle.** A failed short proof is not non-provability, and evaluation cannot handle choice or infinite sets.
- **Related work.** OpenTheory, the HOL importers, Dedukti/Logipedia, autoformalization evaluation (miniF2F, ProofNet, FormalAlign) and LLM-as-judge work. A script confirmed that all 12 references the ARS seats suggested exist in a bibliographic index.
- **Venue risk.** Both say the paper needs an insight beyond "models now translate this".

## 4. Proposed changes to the plan (for v3.3, before the freeze)

These merge the ARS roadmap (15 must-fix items) with Astra's eight round-2 changes. Two points come only from 6.2: the translators see full HOL4 proofs although the task is described as statement translation, and the six defects and three decoys in one package can interact.

1. **Rebuild the framing around one claim.** Make the contribution a measured, evidence-backed translation audit: which checking setups find which HOL4-to-Lean fidelity violations, at what cost, and what executable grounding adds. Fold "does study 1's workflow hold" into it. State contribution (1) as an observation that the audit will test, report it from the audit and the proofs, and drop "certification" or define it narrowly. Write the delta from FormaliSE in three lines.
2. **Write a fidelity contract and freeze it.** Choose and state one notion of fidelity, for example: every HOL4 closure theorem's translation holds, and no target statement is strictly stronger or weaker than HOL4's under a stated type and constant map. Say how unspecified values, `ARB`, choice, `[Nonempty]`, unused binders and finite maps are treated. Then reclassify the mutant list. Under a preservation contract the `HD []` default is a valid model and cannot make an HOL4 theorem false; under a conservativity contract it is a violation, because it makes equations provable that HOL4 does not prove. Choose one and label it accordingly. `[Nonempty]` becomes a decoy where HOL inhabitation justifies it. Re-score the baselines against the same contract.
3. **Redesign the setups so they identify the claim.** Core arms (Neon's version, adopted here): S0 (structural scans only), S1 (Astra alone), S3 (Opus alone), S4 (Astra plus Neon), S5 (Astra plus Neon plus grounding), S1 plus grounding, and S6 (an Opus audit followed by a separate Opus reviewer with Neon's instructions). S6 reuses the S3 scan, and a two-run Opus union or vote is free from S3 repeats, so the cost is lower than 30 full audits suggests (S4 and S5 reuse S1). Drop S2 (Neon alone) unless the budget allows. Separate interactive tool access from scripted grounding in the description of every arm. S7 is optional. Name one primary contrast, S5 against S6 plus grounding (both families, both with the same grounding), on pooled recall and false accusations, paired per defect. Report S4's retention of true findings and rejection of false ones separately, and report joint-miss rates across families.
4. **Change the mutant protocol.** Publish the operators, eligibility rules and sampling before the run. Every mutant needs a checked witness: a HOL4 query, a Lean counterexample or a proof of the negation. Tag each mutant by scope (definition or target statement) and by whether proving would expose it, and include weakened conclusions, dropped conjuncts and redundant hypotheses. Use at most one mutant per module (Neon: not one whole-package copy per mutant, which would cost at least 216 full scans), plus clean modules, with non-interacting bundles only as a secondary test. Hold out 2–3 classes the brief does not name, or cross the brief condition with the setup. Use the two real study-1 defects (`CARD`, integer division) as historical cases. Give every decoy a machine-checked equivalence proof.
5. **Fix sample size and scoring.** Prefer more independent mutants to repeats: Neon would run 3 repeats only on a variance subset, and the core arms once otherwise. Size the study from a pilot of discordant pairs. Report exact or bootstrap intervals that account for clustering, and give per-type results descriptively only. Pre-specify the rule for matching a finding to a mutant (declaration plus mutation class) and a rubric for judging reasons, with two scorers blind to setup, one of them you, and report their agreement. Keep a blinded human-adjudicated subset as a reference outside the operational workflow (6.2). Count false accusations per clean package and per declaration, and add untouched clean packages.
6. **Ground every finding and limit what the oracle claims.** Ground rejected findings as well as accepted ones, and keep "unresolved" as an outcome. State which classes of finding the query tool can decide. Add a typed HOL4 kernel export of the 278 statements as a reference that no model produced, for scans and checks only and not as translator input, so that LLM audit value is isolated (Neon).
7. **Cut scope.** Move Phase 2, the Astra prover, the second proving round and the linear CakeML cost extrapolation out of the ITP paper. Keep one Claude proving round on the clean, repaired base (not the mutants), and report coverage with frozen statements and definitions. Write a one-page outline of the 16-page paper with a page budget. Move the go/no-go to early January, so that it tests whether the primary contrast has data.
8. **Disclose and log.** Keep a log of human effort (task, minutes, whether it needed CakeML or HOL4 expertise). Run a small contamination probe: rename constants and permute theories in a sample, or use a private or post-cutoff theory if one exists. Add a proof-hidden translation condition, or state as a limitation that the translators saw the HOL4 proofs (6.2). Correct the motivating example (the exact mechanism, how many agents in which roles, not "independent"). Pin the Codex, `agy` and Claude Code versions alongside the model strings. Add an anonymisation checklist, and fold the measured results into the plan text: the conditional Sonnet and no-lessons branches have already run.
9. **Add related work.** Cover OpenTheory (Hurd 2011); Obua–Skalberg 2006 and Kaliszyk–Krauss 2013; Assaf–Burel 2015 and Logipedia; Mathport; miniF2F, ProofNet and FormalAlign; Candle (Abrahamsson et al. 2022); mutation validity (Just et al. 2014; Jia and Harman 2011); multiversion independence (Knight and Leveson 1986); and LLM-as-judge work (Zheng et al. 2023).
